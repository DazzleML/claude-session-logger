## What this is

Until this release the logs recorded what Claude Code *did* and only part of what it *said*. A subagent's own narration and reasoning were never captured -- they live in a separate transcript per agent that nothing read -- and Claude's own thinking was skipped on the main thread too. This release reads both, marks failed tool calls, brackets each agent's block with a start and stop line, adds a second timeline that leaves the agents' internal work out, and lets a channel label concurrent agents by id.

Everything here is observable in a plain text file with `tail` and an editor. The automated tests prove the string transformations and the routing; only a person can start a real session, dispatch two real agents, and say whether the resulting files are legible. Several steps ask for a **judgment**, not a pass/fail -- they are marked as such, and an honest "this reads badly" is the most valuable result this document can produce.

## Prerequisites

1. Claude Code with the session-logger plugin at v0.3.19 or later. Confirm the version from the plugin root:
   ```
   python -c "import version; print(version.__version__)"
   ```
2. A throwaway project directory to start test sessions in, so the logs you inspect are clearly yours. Session logs land under `~/.claude/sesslogs/<session-name>__<session-id>_<user>/`; nothing in this checklist writes anywhere else.
3. An editor with bracket matching (vim `%`, or VS Code "Go to Bracket") for Section 6.
4. For Sections 4, 5 and 7 only: the plugin's config file at `~/.claude/plugins/settings/session-logger.json`. **Back it up before editing and restore it in Cleanup.**

**A note on isolation.** These steps exercise the live hook, so they write real log files into your real `~/.claude/sesslogs/`. That is the point -- it is the only place this behavior exists. Nothing here modifies your projects, your git repositories, or any file outside `~/.claude/`. Only the config file is edited, and only in the sections that say so.

**Back up the config** (pick your shell):

**cmd.exe**:
```cmd
copy "%USERPROFILE%\.claude\plugins\settings\session-logger.json" "%TEMP%\session-logger.json.bak"
```

**PowerShell**:
```powershell
Copy-Item "$env:USERPROFILE\.claude\plugins\settings\session-logger.json" "$env:TEMP\session-logger.json.bak"
```

**POSIX**:
```bash
cp ~/.claude/plugins/settings/session-logger.json /tmp/session-logger.json.bak
```

(If the file does not exist, you are on defaults -- note that, and delete the file you create instead of restoring one in Cleanup.)

**Reset between sections:** start a fresh Claude Code session in the throwaway directory. Each session gets its own log directory, so sections never contaminate each other. **Config changes need a fresh session to take effect**, and so do the two new hook subscriptions -- subscriptions load at session start.

**Finding the session's log directory** (pick your shell):

**cmd.exe**:
```cmd
dir /b /o-d "%USERPROFILE%\.claude\sesslogs"
```

**PowerShell**:
```powershell
Get-ChildItem "$env:USERPROFILE\.claude\sesslogs" | Sort-Object LastWriteTime -Descending | Select-Object -First 3 Name
```

**POSIX**:
```bash
ls -t ~/.claude/sesslogs | head -3
```

The newest directory is your session. Inside it the channel files are hidden dot-files: `.sesslog_*`, `.sesslog-main_*`, `.convo_*`, `.shell_*`, `.tools_*`, `.agents_*`, `.agents-<type>_*`.

Throughout, `$D` stands for that directory. Set it once:

**cmd.exe**: `set D=%USERPROFILE%\.claude\sesslogs\<your-session-dir>`
**PowerShell**: `$D = "$env:USERPROFILE\.claude\sesslogs\<your-session-dir>"`
**POSIX**: `D=~/.claude/sesslogs/<your-session-dir>`

## High-Value Verification (~10 minutes)

**If you only have ten minutes**, run these six. They are the reason the release exists. If one fails, the detailed sections below will not save it.

### HV.1 -- A subagent's own words are recorded

Validates: the sidechain reader -- the single largest gap this release closes.

- [ ] **Steps:**
  1. Start a fresh session in the throwaway directory.
  2. Ask Claude to dispatch one subagent with real work, e.g. *"Use the Explore agent to find every file in this directory that mentions 'config'."*
  3. Wait for the agent to finish, then look at its file.

  **PowerShell**: `Get-Content "$D\.agents-explore_*"`
  **POSIX**: `cat "$D"/.agents-explore_*`
  **cmd.exe**: `type "%D%\.agents-explore_*"`
- [ ] **Expected:** the file holds that agent's whole story in order -- the dispatch prompt, an `{AGENT-START:explore: ...}` line, the tool calls the agent ran, `{AGENT-THINK:explore: ...}` lines, one or more `{AGENT:explore: ...}` narration lines, its final report, and an `{AGENT-STOP:explore: stopped (N narration, M thinking, report) }` line whose counts match what you can see above it.
- [ ] **Why this matters:** before this release everything between the dispatch and the report was silently dropped. If the narration and thinking lines are missing, the reader is not running.

### HV.2 -- Claude's own thinking is recorded

Validates: main-thread thinking extraction and the `{THINK: ...}` label.

- [ ] **Steps:** in the same session, ask a question that makes Claude reason for a moment, then:

  **PowerShell**: `Select-String -Path "$D\.convo_*" -Pattern "\{THINK:" | Select-Object -First 3`
  **POSIX**: `grep -m3 "{THINK:" "$D"/.convo_*`
  **cmd.exe**: `findstr /c:"{THINK:" "%D%\.convo_*"`
- [ ] **Expected:** at least one `{THINK: ...}` entry, timestamped, sitting near the `{AI: ...}` entry it belongs to.
- [ ] **Why this matters:** thinking is the bulk of what Claude produces and none of it was captured before.

### HV.3 -- A failed tool call says so

Validates: the `PostToolUseFailure` subscription and the `[FAILED: reason]` marker.

- [ ] **Steps:** ask Claude to read a file that does not exist, e.g. *"Read the file ./definitely-not-here-9f3.md"*, then:

  **PowerShell**: `Select-String -Path "$D\.sesslog_*" -Pattern "\[FAILED:"`
  **POSIX**: `grep "\[FAILED:" "$D"/.sesslog_*`
  **cmd.exe**: `findstr /c:"[FAILED:" "%D%\.sesslog_*"`
- [ ] **Expected:** one line, with the reason inside the frame, e.g. `[[...]] {Read: ./definitely-not-here-9f3.md [FAILED: File does not exist.] }`. The same line appears in `.tools_*`.
- [ ] **Why this matters:** a failed call used to look exactly like a successful one, so a log could not answer "did that work?".

### HV.4 -- The main-thread view exists and is quieter

Validates: the `sesslog-main` channel. **This step is a judgment as much as a check.**

- [ ] **Steps:** after HV.1 (so the session contains a subagent), compare the two timelines:

  **PowerShell**:
  ```powershell
  (Get-Content "$D\.sesslog_*").Count
  (Get-Content "$D\.sesslog-main_*").Count
  Get-Content "$D\.sesslog-main_*" | Select-Object -Last 30
  ```
  **POSIX**:
  ```bash
  wc -l "$D"/.sesslog_* "$D"/.sesslog-main_*
  tail -30 "$D"/.sesslog-main_*
  ```
- [ ] **Expected:** `.sesslog-main_*` is shorter. It contains your prompts, Claude's narration, the main thread's tool calls, the agent dispatch, the START and STOP brackets and the agent's report. It contains **no** `THINK` lines and **none** of the agent's own tool calls or narration.
- [ ] **Judgment:** read it. Is it the file you would actually open to see what happened? Say so either way -- "no different enough to keep" is a legitimate finding and the channel has a one-line off switch.
- [ ] **Why this matters:** the whole channel is justified by being more readable than `sesslog`. If it is not, it should not ship enabled.

### HV.5 -- Two agents of one type are distinguishable

Validates: the agent-id label mode, the reason it exists.

- [ ] **Steps:**
  1. Set the option (see Section 5 for the exact config), start a fresh session.
  2. Ask Claude to dispatch **two Explore agents in one message** on different questions.
  3. Read the per-type file: **POSIX** `cat "$D"/.agents-explore_*`
- [ ] **Expected:** every line carries a short id (`{AGENT:explore/a7c41e0b ...}`, or `{AGENT:a7c41e0b ...}` under `auto-id`), and the two agents' lines carry two different ids. The `AGENT-STOP` line for each carries the full id once, as `[id a7c41e0b9d2f53e18]`.
- [ ] **Why this matters:** two same-type agents write into one file; without ids their interleaved lines are indistinguishable.

### HV.6 -- Nothing that used to work broke

Validates: the release's compatibility promise.

- [ ] **Steps:** in any session from the steps above, confirm the old files still look like themselves:

  **POSIX**: `tail -20 "$D"/.shell_* ; tail -20 "$D"/.tools_* ; tail -20 "$D"/.tasks_*`
- [ ] **Expected:** `.shell_*` still reads as copy-pasteable shell history; `.tools_*` still has tool calls and no prose; task lines still render as before. Successful tool calls are byte-for-byte what they were in v0.3.18 -- no stray markers, no changed labels.
- [ ] **Why this matters:** six units landed at once. The one intended change to default output is that Claude Code's typeless side-queries now show 8 characters of their id instead of 17 (Section 7.3).

## Section 1: The live payload probe (~5 min, do this first in a fresh session)

The building session could not observe what `SubagentStart` actually carries: hook subscriptions load when a session starts, so the very session that added the subscription never received the event. The handler is written to tolerate any shape and records the payload's keys in the debug log. **This section is the only way to learn what the field actually looks like on a live box.**

### 1.1 What SubagentStart carries for a typed agent

- [ ] **Steps:**
  1. Start a **fresh** session (required -- subscriptions load at session start).
  2. Dispatch one typed agent (Explore, or any named agent).
  3. Read the debug log:

  **PowerShell**: `Select-String -Path "$env:USERPROFILE\.claude\logs\hook-debug.log" -Pattern "SubagentStart" | Select-Object -Last 10`
  **POSIX**: `grep "SubagentStart" ~/.claude/logs/hook-debug.log | tail -10`
  **cmd.exe**: `findstr /c:"SubagentStart" "%USERPROFILE%\.claude\logs\hook-debug.log"`
- [ ] **Expected:** at least one line naming the payload's keys.
- [ ] **Record here** (this is the deliverable of the step): the key names present, and whether any of them carries a human-readable description of the agent's task.
- [ ] **Check:** the `{AGENT-START:<type>: ...}` line in `.agents-<type>_*`. If the payload carried a description, the line shows it; if not, it reads `started`. Both are correct -- note which happened.

### 1.2 What SubagentStart carries for a typeless side-query

- [ ] **Steps:** in the same session, work normally for a few minutes so Claude Code runs its own internal side-queries (activity summaries and similar), then look for start lines with no type.
- [ ] **Expected:** **no** `AGENT-START` or `AGENT-STOP` lines for typeless forks -- brackets are for typed agents only, by design. Each side-query still contributes one line to `.agents-untyped_*`.
- [ ] **Check:** `.agents-untyped_*` exists and holds one line per side-query, each labelled `{AGENT:untyped/<8 hex> ...}`.

### 1.3 No fatal errors

- [ ] **Steps:**

  **POSIX**: `grep "FATAL" ~/.claude/logs/hook-debug.log | tail -5`
  **PowerShell**: `Select-String -Path "$env:USERPROFILE\.claude\logs\hook-debug.log" -Pattern "FATAL" | Select-Object -Last 5`
- [ ] **Expected:** no `FATAL` lines with today's timestamp. (Older ones are history.)
- [ ] **Why:** a hook that raises drops the entry silently; the debug log is the only place it surfaces.

## Section 2: Subagent capture in depth (~10 min)

### 2.1 The agent's tool calls are attributed

- [ ] **Steps:** in a session where an agent ran, look at `.sesslog_*` for the agent's calls:

  **POSIX**: `grep "|explore" "$D"/.sesslog_* | head`
- [ ] **Expected:** the agent's calls read `{Grep|explore: ...}` -- the tool, then the agent that made it. They appear at their true time, interleaved with the main thread.
- [ ] **Check:** the same calls also appear in `.agents-explore_*`, collected into that agent's story.

### 2.2 The report is the agent's, not the main thread's

- [ ] **Steps:** find the last `{AGENT:` line before the `AGENT-STOP` line in `.agents-<type>_*`, and compare it with what the agent actually reported in the Claude Code UI.
- [ ] **Expected:** they match. The report is the agent's final message.
- [ ] **Why:** before this release, a shared read cursor could put the *main thread's* text under the agent's label. This is the regression that fix closed.

### 2.3 A resumed agent does not repeat itself

- [ ] **Steps:** if your Claude Code build supports continuing an agent (sending it another message after it stops), do so; otherwise mark this **SKIPPED (build does not support it)**.
- [ ] **Expected:** the second stop adds only the new turns. Nothing from the first run appears twice.
- [ ] **Check:** the per-agent cursor file exists under `~/.claude/session-states/` named `<session-id>.agent-<agent-id>.cursor`.

### 2.4 Ordering and legibility -- **a judgment**

- [ ] **Steps:** work a real half-hour with two or three agents dispatched at different times. Then read `.sesslog_*` straight through.
- [ ] **What to look for:** an agent's tool calls appear live, at their true moment; its narration and thinking can only be read when it stops, so they arrive together as a burst at the end of its run. Timestamps are true either way.
- [ ] **Judgment:** is the interleaving legible, or does the end-of-run burst make the main timeline hard to follow? If it reads badly, say where -- the alternative designs (holding tool calls back, or moving the burst) are recorded in the design document and can be revisited.

### 2.5 An agent that produced nothing

- [ ] **Steps:** interrupt an agent early (Escape), or dispatch one that fails immediately.
- [ ] **Expected:** no crash, no `FATAL`. The stop line reads honestly, e.g. `stopped (0 narration, 0 thinking, no report)`.

## Section 3: Thinking (~5 min)

### 3.1 Where thinking appears by default

- [ ] **Steps:** in a session with both main-thread work and a subagent:

  **POSIX**:
  ```bash
  grep -c "{THINK:" "$D"/.sesslog_* "$D"/.convo_*
  grep -c "{AGENT-THINK:" "$D"/.agents-*_*
  grep -c "THINK" "$D"/.sesslog-main_*
  ```
  **PowerShell**: use `Select-String -Pattern "\{THINK:" -Path ... | Measure-Object -Line`
- [ ] **Expected:** `{THINK: ...}` counts above zero in `.sesslog_*` and `.convo_*`; **zero** of anything with `THINK` in `.sesslog-main_*`.
- [ ] **Expected for `{AGENT-THINK:...}`: possibly zero, and that is not a failure.** Measured on 2026-09-04: a subagent's transcript stores its thinking blocks with the text stripped (the signature is kept, the words are not), so there is often nothing to record. An empty block is never written as an entry. If you do see `{AGENT-THINK:<type>: ...}` lines with real text, that is the other half working -- note it, because it means the build persists them.
- [ ] **Check:** where an `{AGENT-THINK:explore: ...}` entry does appear it carries the agent's identity, so it can never be confused with main-thread thinking.

### 3.2 Turning thinking off for one channel

- [ ] **Steps:** add this to the config, start a fresh session, work briefly:
  ```json
  {"routing": {"channels": {"convo": {"options": {"thinking": false}}}}}
  ```
- [ ] **Expected:** `.convo_*` has no `THINK` lines; `.sesslog_*` still does.

### 3.3 Turning thinking off everywhere

- [ ] **Steps:** replace the config with `{"thinking": false}`, start a fresh session, work briefly.
- [ ] **Expected:** no `THINK` or `AGENT-THINK` lines anywhere -- not in `.sesslog_*`, `.convo_*` or the per-agent files. Narration is untouched.
- [ ] **Why:** this is the global switch; it stops the extraction itself, not just the writing.

### 3.4 The reasoning-only channel

- [ ] **Steps:** config `{"routing": {"channels": {"thinking": {"enabled": true}}}}`, fresh session, work briefly.
- [ ] **Expected:** a `.thinking_*` file appears holding every thinking entry (main thread and agents) and nothing else.

### 3.5 Volume -- **a judgment**

- [ ] **Steps:** after a long working session, compare sizes:

  **POSIX**: `ls -lh "$D"/.sesslog_* "$D"/.sesslog-main_* "$D"/.agents-*`
  **PowerShell**: `Get-ChildItem "$D" -Force | Select-Object Name, Length | Sort-Object Length -Descending`
- [ ] **Expected:** larger than before this release -- thinking is bulky by nature. Nothing should be pathological (a single agent file many times the size of `sesslog`, or a file growing without bound).
- [ ] **Judgment:** is the size acceptable for a day's work? If not, that is an argument for shipping `thinking` off by default, and worth reporting.

## Section 4: The main-thread view (~5 min)

### 4.1 What it contains and what it does not

- [ ] **Steps:** in a session with a subagent, read `.sesslog-main_*` end to end.
- [ ] **Expected present:** your prompts, Claude's narration, the main thread's own tool calls (including failed ones with their marker), the `{Agent: ...}` dispatch, `AGENT-START` / `AGENT-STOP`, and the agent's report.
- [ ] **Expected absent:** every tool call the agent made itself, the agent's narration, and all thinking.
- [ ] **Check:** everything absent here is still present in `.sesslog_*` -- nothing is lost, it is a different view of the same session.

### 4.2 The off switch is one line

- [ ] **Steps:** config `{"routing": {"channels": {"sesslog-main": {"enabled": false}}}}`, fresh session, work briefly.
- [ ] **Expected:** no `.sesslog-main_*` file in the new session's directory. `.sesslog_*` is unaffected.

### 4.3 Thinking back on for it

- [ ] **Steps:** config `{"routing": {"channels": {"sesslog-main": {"options": {"thinking": true}}}}}`, fresh session.
- [ ] **Expected:** `{THINK: ...}` lines appear in `.sesslog-main_*`, while the agents' internal work stays out. The two exclusions are independent.

## Section 5: Agent ids in labels (~10 min)

### 5.1 Turning the mode on

- [ ] **Steps:** put this in the config and start a fresh session:
  ```json
  {
    "routing": {
      "channels": {
        "convo":  {"options": {"agent_label": "id"}},
        "agents": {"options": {"agent_label": "auto-id"}}
      }
    }
  }
  ```
- [ ] **Expected:** in `.convo_*` every agent line reads `{AGENT:explore/a7c41e0b ...}`; inside `.agents-explore_*` the type is dropped and the id kept, `{AGENT:a7c41e0b ...}` -- the filename already says the type.

### 5.2 Two agents of the same type

- [ ] **Steps:** ask Claude to dispatch **two agents of the same type in one message**, on different questions. Read `.agents-<type>_*`.
- [ ] **Expected:** two distinct short ids; every line attributable to one of them; the two `AGENT-STOP` lines carry two different full ids.
- [ ] **Judgment:** with the ids present, can you follow one agent's thread through the interleaved file? That is the entire purpose of the mode.

### 5.3 The short id maps back to the full one

- [ ] **Steps:** take a short id from any label, then find its full form two ways:
  1. In the log: find that agent's `AGENT-STOP` line and read the `[id ...]` suffix.
  2. On disk, by prefix search:

  **POSIX**: `ls ~/.claude/projects/*/<session-id>/subagents/agent-a7c41e0b*.jsonl`
  **PowerShell**: `Get-ChildItem "$env:USERPROFILE\.claude\projects\*\<session-id>\subagents\agent-a7c41e0b*.jsonl"`
- [ ] **Expected:** both give the same full id, and the file found is that agent's transcript.
- [ ] **Why:** the short form is only acceptable because it maps back. If the prefix search misses, the width is wrong.

### 5.4 The default is unchanged

- [ ] **Steps:** remove the `agent_label` settings, fresh session, dispatch an agent.
- [ ] **Expected:** labels read `{AGENT:explore ...}` and `{Bash|explore: ...}` with no id, exactly as in v0.3.18.

## Section 6: Framing and readability (~5 min)

### 6.1 The brace jump still lands, now over thinking bodies

- [ ] **Steps:** open a `.convo_*` file from a session that recorded thinking (thinking bodies often contain code and braces). Put the cursor on the first `{` of a `{THINK:` entry and jump: vim `%`, VS Code "Go to Bracket".
- [ ] **Expected:** the cursor lands on that entry's last `}` -- not somewhere inside the body, not at the end of the file.
- [ ] **Check:** where a body held unbalanced braces you will see the padding outside the frame (`}}}` at the end, or `{{THINK:` at the start). That is the v0.3.18 guarantee holding over the new entry kinds.

### 6.2 The new lines read well under tail

- [ ] **Steps:** **POSIX** `tail -f "$D"/.sesslog_*` (PowerShell: `Get-Content "$D\.sesslog_*" -Wait -Tail 20`) while working, including dispatching an agent.
- [ ] **Expected:** each entry is one line; the `AGENT-START` / `AGENT-STOP` brackets are visually obvious; failed calls stand out.
- [ ] **Judgment:** does the live tail stay readable through an agent's end-of-run burst?

### 6.3 Windows console rendering

- [ ] **Steps:** view a log with thinking in `cmd.exe` (`type`) and in PowerShell (`Get-Content`).
- [ ] **Expected:** no mojibake, no truncated lines, no console errors. Thinking bodies may contain non-ASCII characters -- if any render as `?` or garbage, note the exact line.

## Section 7: Compatibility and the presets (~10 min)

### 7.1 Successful calls are byte-identical

- [ ] **Steps:** if you kept a log from v0.3.18, compare the shape of a simple `{Bash: ...}` or `{Read: ...}` line with a new one for the same tool.
- [ ] **Expected:** identical shape -- same frame, same spacing, no new suffix. Only failures gained a marker.

### 7.2 An existing config still loads

- [ ] **Steps:** restore your own pre-upgrade config (the backup from Prerequisites), start a fresh session.
- [ ] **Expected:** it loads without warnings in `hook-debug.log`; the channels you had enabled behave as before. `sesslog-main` appears as a new file because it ships enabled -- disable it if you do not want it (4.2).

### 7.3 The one intended default change

- [ ] **Steps:** look at `.agents-untyped_*` in any recent session.
- [ ] **Expected:** labels now read `{AGENT:untyped/a000e885 ...}` -- 8 characters of the id, where earlier versions showed all 17. Nothing else about them changed.

### 7.4 The presets do what they say

- [ ] **Steps:** for each preset, copy it to `~/.claude/plugins/settings/session-logger.json`, start a fresh session, work for a minute, then list the files created:

  **POSIX**: `ls -a "$D" | grep '^\.'`
  **PowerShell**: `Get-ChildItem "$D" -Force | Select-Object -ExpandProperty Name`

  | Preset | Expected files |
  |---|---|
  | `session-logger.json` | the eight channels that ship enabled; no `.fileio_*`, `.tools-output_*` or `.thinking_*` |
  | `session-logger-minimal.json` | `.shell_*` and nothing else |
  | `session-logger-conversation-replay.json` | `.convo_*` and nothing else, with no `THINK` lines in it |
  | `session-logger-power-user.json` | every channel, including `.thinking_*`, `.fileio_*`, `.tools-output_*`, plus subtype splits like `.shell-bash_*` |
  | `session-logger-agent-debug.json` | agent files with ids in labels, and no `untyped` lines in `.convo_*` |
- [ ] **Why this matters:** the "only X" presets keep their promise only by naming every channel they do not want. This release rewrote them for exactly that reason.

### 7.5 A fresh install

- [ ] **Steps:** on a machine (or account) that does not have the plugin, install it the documented way and start a session:
  ```
  claude plugin marketplace add "DazzleML/claude-session-logger"
  claude plugin install session-logger@dazzle-claude-plugins
  ```
- [ ] **Expected:** the sesslog directory appears with the default channels, including `.sesslog-main_*`. Dev boxes run from a local directory marketplace, so this is the only way to see what a user actually receives.
- [ ] **Note:** mark **SKIPPED** if you have no clean environment; say so rather than assuming.

## Section 8: Performance (~2 min, after a long session)

### 8.1 The slow-invocation log

- [ ] **Steps:**

  **POSIX**: `cat ~/.claude/logs/session-logger-perf.log`
  **PowerShell**: `Get-Content "$env:USERPROFILE\.claude\logs\session-logger-perf.log"`
  **cmd.exe**: `type "%USERPROFILE%\.claude\logs\session-logger-perf.log"`

## What the automated tests DON'T cover

- **The live `SubagentStart` payload.** Subscriptions load at session start, so the session that added the subscription cannot observe it. Section 1 is the only source of truth.
- **Real subagent transcripts.** The tests build JSONL fixtures; only a real agent produces real timing, real interruptions, and a transcript that may not be flushed when the hook runs.
- **Whether the main-thread view is worth having.** HV.4 and 4.1 are judgments about readability; no assertion can make them.
- **Whether the end-of-run burst is legible** in a real multi-agent stretch (2.4).
- **Volume in practice.** Thinking is bulky; the tests use short strings (3.5).
- **Editor bracket matching.** The tests prove the brace counts; only vim and VS Code prove the jump (6.1).
- **Windows console rendering** of thinking bodies, which often carry code and non-ASCII text (6.3).
- **A real install** from the published marketplace (7.5).
- **Config isolation.** The tests use temp homes; a real user shares the process with their own `~/.claude`.
